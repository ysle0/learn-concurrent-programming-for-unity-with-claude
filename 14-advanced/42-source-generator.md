# 42. Source Generator 활용

## 개요

**Source Generator**는 C# 컴파일러(Roslyn)의 확장 기능으로, **컴파일 타임에 자동으로 코드를 생성**하는 메커니즘입니다. 런타임 리플렉션 없이 직렬화, 보일러플레이트 코드, 비동기 래퍼 등을 자동 생성하여 **성능 향상**과 **AOT(Ahead-of-Time) 호환성**을 동시에 달성합니다. Unity에서는 MemoryPack, R3, MessagePack 등 주요 라이브러리가 Source Generator를 활용하고 있습니다.

---

## 1. Source Generator 기본 개념

### 컴파일 타임 코드 생성이란?

```
┌─────────────────────────────────────────────────────────┐
│                   컴파일 파이프라인                        │
│                                                         │
│  [소스 코드] → [구문 분석] → [Source Generator] → [코드 생성]  │
│                                │                        │
│                         생성된 코드가                      │
│                         컴파일에 포함됨                     │
│                                ↓                        │
│              [최종 어셈블리 (원본 + 생성된 코드)]              │
└─────────────────────────────────────────────────────────┘
```

Source Generator는 **컴파일 과정 중간에 실행**되어, 기존 소스 코드를 분석하고 새로운 소스 코드를 추가합니다. 기존 코드를 **수정하지 않고 추가만** 할 수 있다는 점이 핵심 특징입니다.

### 핵심 특징 요약

| 특징 | 설명 |
|------|------|
| **추가 전용** | 기존 코드를 수정할 수 없고, 새 코드만 추가 가능 |
| **컴파일 타임** | 빌드 시점에 실행되어 런타임 오버헤드 없음 |
| **Roslyn 기반** | C# 컴파일러의 공식 API를 사용 |
| **AOT 호환** | IL2CPP, NativeAOT 등 AOT 환경에서 안전하게 동작 |
| **IntelliSense 지원** | 생성된 코드에 대해 IDE 자동 완성 제공 |

## 2. Source Generator vs 리플렉션

### 성능 비교

```csharp
using UnityEngine;
using System;
using System.Diagnostics;
using System.Reflection;

public class ReflectionVsSourceGeneratorBenchmark : MonoBehaviour
{
    // =============================================
    // 리플렉션 기반 직렬화 (런타임 비용 발생)
    // =============================================

    public static string SerializeWithReflection(object obj)
    {
        // 런타임에 타입 정보를 조회 - 매번 비용 발생
        Type type = obj.GetType();
        PropertyInfo[] properties = type.GetProperties(
            BindingFlags.Public | BindingFlags.Instance);

        var sb = new System.Text.StringBuilder();
        sb.Append("{");

        for (int i = 0; i < properties.Length; i++)
        {
            if (i > 0) sb.Append(",");
            string name = properties[i].Name;
            object value = properties[i].GetValue(obj); // 박싱 발생 가능
            sb.Append($"\"{name}\":\"{value}\"");
        }

        sb.Append("}");
        return sb.ToString();
    }

    // =============================================
    // Source Generator 기반 직렬화 (컴파일 타임에 코드 생성)
    // =============================================

    // Source Generator가 아래와 같은 코드를 자동 생성
    // 리플렉션 없이 직접 프로퍼티에 접근하므로 매우 빠름
    /*
    // <auto-generated/>
    public static string SerializePlayerData(PlayerData obj)
    {
        var sb = new System.Text.StringBuilder();
        sb.Append("{");
        sb.Append("\"Name\":\""); sb.Append(obj.Name); sb.Append("\"");
        sb.Append(",\"Score\":"); sb.Append(obj.Score);
        sb.Append(",\"Level\":"); sb.Append(obj.Level);
        sb.Append("}");
        return sb.ToString();
    }
    */

    private void Start()
    {
        var data = new PlayerData { Name = "Hero", Score = 9999, Level = 50 };
        int iterations = 100000;

        // 리플렉션 방식 벤치마크
        var sw = Stopwatch.StartNew();
        for (int i = 0; i < iterations; i++)
        {
            SerializeWithReflection(data);
        }
        sw.Stop();
        UnityEngine.Debug.Log($"리플렉션: {sw.ElapsedMilliseconds}ms");

        // Source Generator 방식은 직접 프로퍼티 접근이므로
        // 일반적으로 5~10배 빠름
    }
}

public class PlayerData
{
    public string Name { get; set; }
    public int Score { get; set; }
    public int Level { get; set; }
}
```

### 비교표

| 항목 | 리플렉션 | Source Generator |
|------|----------|------------------|
| **실행 시점** | 런타임 | 컴파일 타임 |
| **성능** | 느림 (타입 조회, 박싱) | 빠름 (직접 접근) |
| **AOT 호환성** | 제한적 (IL2CPP 문제) | 완전 호환 |
| **메모리 할당** | 많음 (박싱, 임시 객체) | 최소 |
| **타입 안전성** | 런타임 에러 가능 | 컴파일 타임 검증 |
| **코드 가독성** | 유지 가능 | 생성 코드는 별도 파일 |
| **IL2CPP 스트리핑** | 리플렉션 대상 보존 필요 | 문제 없음 |

```csharp
// ❌ 리플렉션 방식 - AOT 환경에서 문제 발생 가능
public T Deserialize<T>(byte[] data) where T : new()
{
    var obj = new T();
    var type = typeof(T);

    foreach (var prop in type.GetProperties())
    {
        // IL2CPP에서 코드 스트리핑으로 실패할 수 있음
        prop.SetValue(obj, ReadValue(prop.PropertyType));
    }

    return obj;
}

// ✅ Source Generator 방식 - AOT 안전
// [MemoryPackable] 어트리뷰트만 붙이면 컴파일 타임에 코드 생성
// [MemoryPackable]
// public partial class PlayerData
// {
//     public string Name { get; set; }
//     public int Score { get; set; }
// }
// → 컴파일 시 Serialize/Deserialize 메서드 자동 생성
```

## 3. Source Generator 기본 구조

### ISourceGenerator (기본 인터페이스)

```csharp
// Source Generator 프로젝트 (.NET Standard 2.0 타겟)
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.Text;
using System.Text;

/// <summary>
/// ISourceGenerator: 가장 기본적인 Source Generator 인터페이스
/// 전체 컴파일 컨텍스트를 받아 코드를 생성합니다.
/// </summary>
[Generator]
public class BasicSourceGenerator : ISourceGenerator
{
    // 초기화: 추가 분석이 필요한 구문을 등록
    public void Initialize(GeneratorInitializationContext context)
    {
        // SyntaxReceiver를 등록하여 관심 있는 구문 노드를 수집
        context.RegisterForSyntaxNotifications(() => new MySyntaxReceiver());
    }

    // 실행: 실제 코드 생성
    public void Execute(GeneratorExecutionContext context)
    {
        // SyntaxReceiver에서 수집한 정보로 코드 생성
        if (context.SyntaxReceiver is not MySyntaxReceiver receiver)
            return;

        foreach (var classDeclaration in receiver.CandidateClasses)
        {
            // 시맨틱 모델로 타입 정보 조회
            var model = context.Compilation.GetSemanticModel(classDeclaration.SyntaxTree);
            var symbol = model.GetDeclaredSymbol(classDeclaration) as INamedTypeSymbol;

            if (symbol == null) continue;

            // 코드 생성
            string generatedCode = GenerateCode(symbol);

            // 컴파일에 추가
            context.AddSource(
                $"{symbol.Name}_Generated.g.cs",
                SourceText.From(generatedCode, Encoding.UTF8));
        }
    }

    private string GenerateCode(INamedTypeSymbol symbol)
    {
        return $@"
// <auto-generated/>
namespace {symbol.ContainingNamespace.ToDisplayString()}
{{
    partial class {symbol.Name}
    {{
        public string ToDebugString()
        {{
            return $""[{symbol.Name}] Generated at compile time"";
        }}
    }}
}}";
    }
}
```

### IIncrementalGenerator (권장 - 성능 최적화)

```csharp
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp.Syntax;
using System.Collections.Immutable;
using System.Text;

/// <summary>
/// IIncrementalGenerator: 증분 Source Generator
/// 변경된 파일만 재처리하여 컴파일 속도를 크게 향상시킵니다.
/// Unity 2022.2+ 및 .NET 6+에서 권장됩니다.
/// </summary>
[Generator]
public class IncrementalSourceGeneratorExample : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // 1단계: 관심 있는 구문 노드를 필터링 (빠르게 실행)
        IncrementalValuesProvider<ClassDeclarationSyntax> classDeclarations =
            context.SyntaxProvider
                .CreateSyntaxProvider(
                    // 구문 필터 - 빠른 검사
                    predicate: static (node, _) => IsTargetClass(node),
                    // 시맨틱 변환 - 상세 분석
                    transform: static (ctx, _) => GetTargetClass(ctx))
                .Where(static m => m is not null)!;

        // 2단계: 컴파일 정보와 결합
        IncrementalValueProvider<(Compilation, ImmutableArray<ClassDeclarationSyntax>)>
            compilationAndClasses = context.CompilationProvider
                .Combine(classDeclarations.Collect());

        // 3단계: 코드 생성 등록
        context.RegisterSourceOutput(compilationAndClasses,
            static (spc, source) => Execute(source.Item1, source.Item2, spc));
    }

    // 빠른 구문 필터: partial class인지, 특정 어트리뷰트가 있는지 검사
    private static bool IsTargetClass(SyntaxNode node)
    {
        return node is ClassDeclarationSyntax classDecl
            && classDecl.Modifiers.Any(Microsoft.CodeAnalysis.CSharp.SyntaxKind.PartialKeyword)
            && classDecl.AttributeLists.Count > 0;
    }

    private static ClassDeclarationSyntax? GetTargetClass(
        GeneratorSyntaxContext context)
    {
        var classDecl = (ClassDeclarationSyntax)context.Node;
        // 시맨틱 분석으로 정확한 어트리뷰트 확인
        var symbol = context.SemanticModel.GetDeclaredSymbol(classDecl);

        if (symbol == null) return null;

        foreach (var attr in symbol.GetAttributes())
        {
            if (attr.AttributeClass?.Name == "GenerateSerializerAttribute")
                return classDecl;
        }

        return null;
    }

    private static void Execute(
        Compilation compilation,
        ImmutableArray<ClassDeclarationSyntax> classes,
        SourceProductionContext context)
    {
        foreach (var classDecl in classes)
        {
            var model = compilation.GetSemanticModel(classDecl.SyntaxTree);
            var symbol = model.GetDeclaredSymbol(classDecl) as INamedTypeSymbol;

            if (symbol == null) continue;

            string code = GenerateSerializer(symbol);
            context.AddSource($"{symbol.Name}_Serializer.g.cs", code);
        }
    }

    private static string GenerateSerializer(INamedTypeSymbol symbol)
    {
        var sb = new StringBuilder();
        sb.AppendLine("// <auto-generated/>");
        sb.AppendLine($"namespace {symbol.ContainingNamespace.ToDisplayString()}");
        sb.AppendLine("{");
        sb.AppendLine($"    partial class {symbol.Name}");
        sb.AppendLine("    {");
        sb.AppendLine("        // Source Generator가 생성한 직렬화 메서드");
        sb.AppendLine("    }");
        sb.AppendLine("}");
        return sb.ToString();
    }
}
```

### ISourceGenerator vs IIncrementalGenerator 비교

| 항목 | ISourceGenerator | IIncrementalGenerator |
|------|------------------|----------------------|
| **도입 시기** | .NET 5 / C# 9 | .NET 6 / C# 10 |
| **증분 컴파일** | 지원 안 함 (매번 전체 실행) | 지원 (변경분만 재처리) |
| **IDE 성능** | 느릴 수 있음 | 빠름 |
| **구현 복잡도** | 상대적으로 단순 | 파이프라인 설계 필요 |
| **Unity 지원** | 2021.3+ | 2022.2+ |
| **권장 여부** | 레거시 | 신규 프로젝트 권장 |

## 5. MemoryPack의 Source Generator 활용 사례

### MemoryPack 소개

MemoryPack은 neuecc(Cysharp)가 개발한 **세계 최고 수준의 고성능 바이너리 직렬화** 라이브러리로, Source Generator를 활용하여 **리플렉션 없이** 직렬화 코드를 생성합니다.

```csharp
using MemoryPack;
using UnityEngine;
using Cysharp.Threading.Tasks;
using System.Threading;

// =============================================
// MemoryPack 기본 사용법
// =============================================

// [MemoryPackable] 어트리뷰트와 partial 키워드가 핵심
// 컴파일 타임에 Serialize/Deserialize 코드가 자동 생성됨
[MemoryPackable]
public partial class GameState
{
    public int CurrentLevel { get; set; }
    public float PlayTime { get; set; }
    public string PlayerName { get; set; }
    public Vector3Serializable Position { get; set; }
    public int[] InventoryItemIds { get; set; }
}

// Unity의 Vector3는 직접 직렬화할 수 없으므로 래퍼 사용
[MemoryPackable]
public partial struct Vector3Serializable
{
    public float X { get; set; }
    public float Y { get; set; }
    public float Z { get; set; }

    public Vector3 ToVector3() => new Vector3(X, Y, Z);

    public static Vector3Serializable FromVector3(Vector3 v) =>
        new Vector3Serializable { X = v.x, Y = v.y, Z = v.z };
}

public class MemoryPackExample : MonoBehaviour
{
    private async void Start()
    {
        var token = this.destroyCancellationToken;
        await DemonstrateMemoryPack(token);
    }

    private async UniTask DemonstrateMemoryPack(CancellationToken token)
    {
        // =============================================
        // 직렬화 / 역직렬화
        // =============================================

        var state = new GameState
        {
            CurrentLevel = 10,
            PlayTime = 3600.5f,
            PlayerName = "용사",
            Position = Vector3Serializable.FromVector3(
                new Vector3(10f, 0f, 20f)),
            InventoryItemIds = new[] { 1, 5, 12, 33 }
        };

        // 직렬화 - Source Generator가 생성한 코드를 사용
        // 리플렉션 없이 직접 멤버에 접근하므로 매우 빠름
        byte[] serialized = MemoryPackSerializer.Serialize(state);
        Debug.Log($"직렬화 크기: {serialized.Length} bytes");

        // 역직렬화
        GameState deserialized = MemoryPackSerializer.Deserialize<GameState>(serialized);
        Debug.Log($"레벨: {deserialized.CurrentLevel}, " +
                  $"플레이어: {deserialized.PlayerName}");

        // =============================================
        // 비동기 스트림 직렬화 (네트워크 전송 시 유용)
        // =============================================

        using var stream = new System.IO.MemoryStream();
        await MemoryPackSerializer.SerializeAsync(stream, state, cancellationToken: token);

        stream.Position = 0;
        var fromStream = await MemoryPackSerializer.DeserializeAsync<GameState>(
            stream, cancellationToken: token);

        Debug.Log($"스트림 역직렬화: {fromStream.PlayerName}");
    }
}
```

### MemoryPack Source Generator가 생성하는 코드 (개념)

```csharp
// Source Generator가 자동 생성하는 코드의 개념적 구조
// (실제 생성 코드는 더 최적화되어 있음)

// <auto-generated/>
partial class GameState : IMemoryPackable<GameState>
{
    // 직렬화: 리플렉션 없이 직접 멤버 접근
    static void IMemoryPackable<GameState>.Serialize<TBufferWriter>(
        ref MemoryPackWriter<TBufferWriter> writer,
        scoped ref GameState? value)
    {
        if (value == null)
        {
            writer.WriteNullObjectHeader();
            return;
        }

        writer.WriteObjectHeader(5); // 멤버 수
        writer.WriteValue(value.CurrentLevel);
        writer.WriteValue(value.PlayTime);
        writer.WriteString(value.PlayerName);
        writer.WritePackable(value.Position);
        writer.WriteArray(value.InventoryItemIds);
    }

    // 역직렬화: 컴파일 타임에 타입이 확정됨
    static void IMemoryPackable<GameState>.Deserialize(
        ref MemoryPackReader reader,
        scoped ref GameState? value)
    {
        if (!reader.TryReadObjectHeader(out var count))
        {
            value = null;
            return;
        }

        var v = new GameState();
        if (count > 0) v.CurrentLevel = reader.ReadValue<int>();
        if (count > 1) v.PlayTime = reader.ReadValue<float>();
        if (count > 2) v.PlayerName = reader.ReadString();
        if (count > 3) reader.ReadPackable(ref v.Position);
        if (count > 4) v.InventoryItemIds = reader.ReadArray<int>();
        value = v;
    }
}
```

## 6. R3의 Source Generator 활용 사례

### ObservableProperty 자동 생성

R3는 Source Generator를 사용하여 `[ObservableProperty]` 어트리뷰트가 붙은 필드에 대해 자동으로 ReactiveProperty 래핑 코드를 생성합니다.

```csharp
using R3;
using UnityEngine;
using System;

// =============================================
// R3 Source Generator 활용
// =============================================

// partial class 필수!
public partial class PlayerViewModel : MonoBehaviour
{
    // [ObservableProperty] 어트리뷰트를 필드에 붙이면
    // Source Generator가 자동으로 ReactiveProperty를 생성합니다.
    // 필드명 앞의 _가 제거되고 PascalCase로 프로퍼티가 생성됩니다.

    [ObservableProperty]
```

### INotifyPropertyChanged 자동 구현 Source Generator

```csharp
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp;
using Microsoft.CodeAnalysis.CSharp.Syntax;
using Microsoft.CodeAnalysis.Text;
using System.Collections.Generic;
using System.Linq;
using System.Text;

[Generator]
public class AutoNotifyGenerator : ISourceGenerator
{
    public void Initialize(GeneratorInitializationContext context)
    {
        // 어트리뷰트 소스를 항상 추가
        context.RegisterForPostInitialization(ctx =>
        {
            ctx.AddSource("AutoNotifyAttribute.g.cs", @"
using System;

namespace MyGenerators
{
    [AttributeUsage(AttributeTargets.Class)]
    internal sealed class AutoNotifyAttribute : Attribute { }

    [AttributeUsage(AttributeTargets.Field)]
    internal sealed class NotifyPropertyAttribute : Attribute { }
}");
        });

        context.RegisterForSyntaxNotifications(() => new SyntaxReceiver());
    }

    public void Execute(GeneratorExecutionContext context)
    {
        if (context.SyntaxReceiver is not SyntaxReceiver receiver)
            return;

        foreach (var classDecl in receiver.CandidateClasses)
        {
            var model = context.Compilation.GetSemanticModel(classDecl.SyntaxTree);
            var classSymbol = model.GetDeclaredSymbol(classDecl) as INamedTypeSymbol;

            if (classSymbol == null) continue;

            // [AutoNotify] 어트리뷰트 확인
            bool hasAutoNotify = classSymbol.GetAttributes()
                .Any(a => a.AttributeClass?.Name == "AutoNotifyAttribute");

            if (!hasAutoNotify) continue;

            // [NotifyProperty] 필드 수집
            var fields = new List<(string FieldName, string PropertyName, string TypeName)>();

            foreach (var member in classSymbol.GetMembers())
            {
                if (member is IFieldSymbol field &&
                    field.GetAttributes().Any(
                        a => a.AttributeClass?.Name == "NotifyPropertyAttribute"))
                {
                    string fieldName = field.Name;
                    // _health → Health, health → Health
                    string propName = fieldName.TrimStart('_');
                    propName = char.ToUpper(propName[0]) + propName.Substring(1);

                    fields.Add((fieldName, propName, field.Type.ToDisplayString()));
                }
            }

            if (fields.Count == 0) continue;

            // 코드 생성
            string code = GenerateNotifyClass(classSymbol, fields);
            context.AddSource($"{classSymbol.Name}_AutoNotify.g.cs",
                SourceText.From(code, Encoding.UTF8));
        }
    }

    private string GenerateNotifyClass(
        INamedTypeSymbol classSymbol,
        List<(string FieldName, string PropertyName, string TypeName)> fields)
    {
        var ns = classSymbol.ContainingNamespace.ToDisplayString();
        var className = classSymbol.Name;

        var sb = new StringBuilder();
        sb.AppendLine("// <auto-generated/>");
        sb.AppendLine("using System.ComponentModel;");
        sb.AppendLine("using System.Runtime.CompilerServices;");
        sb.AppendLine();
        sb.AppendLine($"namespace {ns}");
        sb.AppendLine("{");
        sb.AppendLine($"    partial class {className} : INotifyPropertyChanged");
        sb.AppendLine("    {");
        sb.AppendLine("        public event PropertyChangedEventHandler PropertyChanged;");
        sb.AppendLine();
        sb.AppendLine("        private void OnPropertyChanged([CallerMemberName] string propertyName = null)");
        sb.AppendLine("        {");
        sb.AppendLine("            PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));");
        sb.AppendLine("        }");

        foreach (var (fieldName, propName, typeName) in fields)
        {
            sb.AppendLine();
            sb.AppendLine($"        public {typeName} {propName}");
            sb.AppendLine("        {");
            sb.AppendLine($"            get => {fieldName};");
            sb.AppendLine("            set");
            sb.AppendLine("            {");
            sb.AppendLine($"                if (!Equals({fieldName}, value))");
            sb.AppendLine("                {");
            sb.AppendLine($"                    {fieldName} = value;");
            sb.AppendLine($"                    OnPropertyChanged();");
            sb.AppendLine("                }");
            sb.AppendLine("            }");
            sb.AppendLine("        }");
        }

        sb.AppendLine("    }");
        sb.AppendLine("}");

        return sb.ToString();
    }

    private class SyntaxReceiver : ISyntaxReceiver
    {
        public List<ClassDeclarationSyntax> CandidateClasses { get; } = new();

        public void OnVisitSyntaxNode(SyntaxNode syntaxNode)
        {
            if (syntaxNode is ClassDeclarationSyntax classDecl &&
                classDecl.Modifiers.Any(SyntaxKind.PartialKeyword) &&
                classDecl.AttributeLists.Count > 0)
            {
                CandidateClasses.Add(classDecl);
            }
        }
    }
}
```

```csharp
public class SourceGeneratorDebugHelper : MonoBehaviour
{
    private void Start()
    {
        // partial class의 메서드가 존재하는지 확인
        var type = typeof(PlayerViewModel);
        var methods = type.GetMethods();

        Debug.Log($"=== {type.Name} 메서드 목록 ===");
        foreach (var method in methods)
        {
            if (method.DeclaringType == type)
            {
                Debug.Log($"  {method.ReturnType.Name} {method.Name}()");
            }
        }

        // 생성된 프로퍼티 확인
        var properties = type.GetProperties();
        Debug.Log($"=== {type.Name} 프로퍼티 목록 ===");
        foreach (var prop in properties)
        {
            if (prop.DeclaringType == type)
            {
                Debug.Log($"  {prop.PropertyType.Name} {prop.Name}");
            }
        }
    }
}
```

```csharp
    {

        var diagnostic = Diagnostic.Create(
            new DiagnosticDescriptor(
                "SG001",
                "Source Generator 디버그",

                "Debug",

                isEnabledByDefault: true),
            Location.None,
            "MyClass");

        // 방법 3: 파일에 로그 출력
        // (개발 중에만 사용, 배포 시 제거)
        #if DEBUG
        System.IO.File.AppendAllText(
            "/tmp/source_generator_log.txt",
            $"[{System.DateTime.Now}] Execute called\n");
        #endif
    }
}
```

### Source Generator의 제한사항

```csharp
// =============================================
// 제한사항 1: 코드 추가만 가능 (수정 불가)
// =============================================

// ❌ 기존 코드를 수정할 수 없음
// Source Generator는 새로운 파일을 추가하는 것만 가능
// 기존 메서드의 본문을 바꾸거나, 필드를 제거할 수 없음

// ✅ partial class를 활용하여 새 멤버를 추가하는 방식으로 구현
[AutoNotify]
public partial class MyClass   // 사용자 작성
{
    [NotifyProperty]
    private int _value;
}

// Source Generator가 추가:
// partial class MyClass         // 자동 생성
// {
//     public int Value { get; set; }
// }

// =============================================
// 제한사항 2: partial 키워드 필수
// =============================================

// ❌ partial이 없으면 Source Generator가 같은 이름의 클래스를 추가할 수 없음
public class NonPartialClass   // Source Generator 확장 불가
{
    // ...
}

// ✅ partial 키워드를 반드시 붙여야 함
public partial class ExtensibleClass   // Source Generator 확장 가능
{
    // ...
}

// =============================================
// 제한사항 3: .NET Standard 2.0 제약
// =============================================

// Source Generator 프로젝트는 .NET Standard 2.0을 타겟해야 함
// 따라서 최신 C# 기능 중 일부를 사용할 수 없음:
// - Span<T> (직접 사용 제한)
// - record 타입 (제한적)
// - 일부 최신 BCL API

// =============================================
// 제한사항 4: 순환 참조 불가
// =============================================

// ❌ Source Generator가 생성한 코드가 다른 Source Generator의 입력이 될 수 없음
// Generator A → 생성 코드 → Generator B 입력 (불가)

// ✅ 하나의 Source Generator에서 모든 관련 코드를 생성
```

```csharp
// Unity 2021.3: Microsoft.CodeAnalysis 3.x
```

## 주의사항

1. **partial 키워드 필수**: Source Generator로 확장할 클래스에는 반드시 `partial` 키워드를 붙여야 합니다.
2. **RoslynAnalyzer 라벨**: Unity에서 Source Generator DLL에 "RoslynAnalyzer" 라벨을 설정하지 않으면 동작하지 않습니다.
3. **AOT 환경 테스트**: IL2CPP 빌드에서 반드시 동작을 확인하세요. Source Generator가 생성한 코드가 AOT 환경에서 올바르게 컴파일되는지 검증이 필요합니다.
4. **컴파일 시간 증가**: 복잡한 Source Generator는 컴파일 시간을 늘릴 수 있습니다. IIncrementalGenerator를 사용하여 증분 컴파일을 지원하세요.
5. **생성 코드 검토**: 생성된 코드를 반드시 확인하세요. IDE의 "Go to Definition"이나 Analyzers 노드에서 확인할 수 있습니다.
6. **순환 참조 금지**: Source Generator 프로젝트가 사용자 프로젝트를 참조하면 순환 참조가 발생합니다.
7. **Unity 에디터 재시작**: Source Generator DLL을 업데이트한 후에는 Unity 에디터를 재시작해야 할 수 있습니다.
8. **네임스페이스 충돌**: 생성된 코드의 네임스페이스가 기존 코드와 충돌하지 않도록 주의하세요.
